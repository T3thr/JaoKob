## 1. ทำไมห้ามเจนหน้าจอ UX/UI ทั้งภาพด้วย Single-Pass Image Diffusion (`บทเรียนจาก v1`)

จากการตรวจชุดภาพ `docs/design-system/ux-mockups/v1/` พบว่าการสั่งโมเดลสร้างภาพวาดทั้งฉาก + กรอบ UI + ไอคอน + ตัวหนังสือไทยในครั้งเดียวทีละรูป ทำให้เกิดปัญหา **UI Component Drift และ AI Slop** รุนแรง 5 ประการที่ห้ามเกิดซ้ำใน `v2` เด็ดขาด:

1. **แถบสถานะ (`Top HUD Capsule`) กลายพันธุ์ 6 แบบใน 10 รูป:** บางรูปเป็นแคปซูลกระจก บางรูปกลายเป็นป้ายไม้พันเถาวัลย์ บางรูปเรียงแนวตั้ง บางรูปสร้อยสายใยหายไป และไอคอน `ใจ` เปลี่ยนไปมาระหว่างดาว 4 แฉก ใบพัด 3 แฉก และสามง่าม
2. **ทำลายมาตรฐานตัวละครครึ่งตัว (`Tachie v2`):** แทนที่จะนำสไปรต์ครึ่งตัว `versions/v2/*.png` มาวางบนเวทีตามกฎแถบสายตา `52–68%` ของ [ADR-P0-032](../../adr/ADR-P0-032-living-fantasy-canon-peuak-miracle-doll-and-vn-stage-blocking.md) โมเดลกลับวาดตัวละครเต็มตัวนั่งขัดสมาธิหรือยืนเต็มตัวใหม่ทุกภาพจนดูไม่เหมือนเกม Visual Novel เดียวกัน
3. **ไอคอนหลุดโลกของกบ (`Out-of-World Clipart Slop`):** มีการวาด **กระเป๋าเป้หนังเดินป่าของมนุษย์** ในการ์ดเตรียมของของกบสูง 45 ซม., วาด **รอยเท้ามนุษย์ 5 นิ้ว** แทนรอยเท้ากบ และใส่เหรียญ `ต.♡ป.` มั่วในฉากจบกลับบึงน้ำใส
4. **คำภาษาไทยสะกดเพี้ยนจากโมเดลวาดภาพ:** เช่น `ตามข้อเท้าให้แล็อก` (ที่ถูกคือ `ดามข้อเท้า`), `ถามไถ่เด็อก` (`เตื๊อก`), `เย็บกระตุม` (`กระดุม`), `ตื่นด้วยลำแข้ง` (`ยืนด้วยลำแข้ง`) และ `ด.♡ป.` (`ต.♡ป.`)
5. **Desktop กับ Mobile ของโหมดเดียวกันหน้าตาเหมือนคนละเกม:** โดยเฉพาะโหมด 2, โหมด 3 และโหมด 5 ที่การ์ดบนมือถือและบนคอมพิวเตอร์ใช้คนละโครงสร้างกันอย่างสิ้นเชิง

## 2. สถาปัตยกรรมใหม่: `Figma-Style Atomic Component Pipeline` (แบ่งหน้าที่ AI Art กับ Deterministic UI)

เพื่อให้ทุกหน้าจอทั้ง 5 โหมดบนโทรศัพท์และคอมพิวเตอร์ **มีมาตรฐาน Component เดียวกัน 100% เสมือนออกแบบใน Figma** และยังคงความอบอุ่นของงานศิลป์ทำมือ ให้แยกเลเยอร์การผลิตเป็น 4 ชั้นอย่างเคร่งครัด:

```text
[Layer A: Master Device Shells]   กรอบเครื่อง MacBook Pro (Chrome) 1 ไฟล์ + iPhone 16 Pro (Safari) 1 ไฟล์ ใช้ซ้ำทุกรูป
        ▲
[Layer B: Atomic UI Components]   1 ไฟล์ CSS/SVG กลาง (TopHUD, SaaDialogue, TactileCard, ClashBar, StrandCard) + ฟอนต์ Sarabun แท้
        ▲
[Layer C: Real Canonical Assets]  สไปรต์ตัวละคร Tachie v2 พื้นโปร่งใสจริง + ไอคอนของสะสม 512×512 จริงจาก assets/images/
        ▲
[Layer D: Stage Background/Plate] ฉากหลังจริงจาก assets/images/backgrounds/ (ใช้ Image Gen เฉพาะฉากซูมมือโหมด 4 หรือเงาผนังแบบไร้ตัวหนังสือ)
```

> [!IMPORTANT]
> **กฎเหล็กเครื่องมือเรนเดอร์ (ห้ามใช้ Playwright / ห้ามใช้ npm):**
> บนเครื่องนี้มี Google Chrome ติดตั้งอยู่แล้วที่ `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` และมี `Python 3` พร้อม `Pillow (PIL)` ติดตั้งอยู่แล้ว ให้ใช้ Chrome CLI โหมด `--headless=new` จับภาพหน้าจอ Viewport จาก HTML/CSS Component Harness โดยตรง (ใช้เวลาไม่เกิน 1 วินาทีต่อภาพ) แล้วใช้ Python `Pillow` วางภาพ Viewport ลงในกรอบเครื่อง MacBook Pro และ iPhone 16 Pro **ห้ามค้นหาหรือรัน Playwright / npx เด็ดขาด**

### 3.2 Master Component 1: `<TopHudCapsule />` (ต้องเหมือนกันทุกพิกเซลในโหมด 1, 2, 3 และ 5)

- **โครงสร้างแนวนอนแถวเดียวเสมอ** (ห้ามเรียงซ้อนแนวตั้ง และห้ามเปลี่ยนกรอบเป็นป้ายไม้เถาวัลย์):
  1. **กลุ่มสถานะ 3 ค่า (ใช้ SVG เส้นคมชุดเดียวกันทุกรูป):**
     - `กาย` + **ไอคอนใบบัว** + เม็ดกลม 5 เม็ด
     - `ใจ` + **ไอคอนดาวสามแฉก** (ตามลายปักบนเสื้อสีฟ้าของเจ้ากบ — ห้ามใช้ดาว 4 แฉกหรือใบพัด!) + เม็ดกลม 5 เม็ด
     - `แรง` + **ไอคอนขากบสามนิ้วมีพังผืด** (ห้ามใช้รอยเท้าคน 5 นิ้วหรือขามนุษย์!) + เม็ดกลม 5 เม็ด
  2. **เส้นคั่นบาง** + **สร้อยสายใยด้ายถัก 3 เส้น** (สีส้มสนิมพี่ก้าม · สีเหลืองแดดเจ้าฟิ้ว · สีกรมท่าเจ้าเตื๊อก พร้อมจุดปมด้ายบนเส้น)
  3. **เส้นคั่นบาง** + **ปุ่มกระเป๋าสานกก 4 ช่อง** (ไอคอนตารางสาน `2×2` ช่อง — ห้ามใช้รูปกระเป๋าเป้หนังมนุษย์!)
  4. **ปุ่มฟันเฟืองตั้งค่า** (`44×44 px`) มุมขวาสุด (บนมือถือย่อข้อความกำกับให้กระชับแต่คงไอคอนและลำดับเดิม 100%)

### 3.3 Master Component 2: `<VnTachieStage />` (กฎการจัดวางตัวละครจริงบนเวที)

- **บังคับใช้ไฟล์ภาพตัวละครครึ่งตัว `Tachie v2` พื้นโปร่งใสจริง** จาก `assets/images/characters/*/versions/v2/*.png` ในโหมด 1, 2, 3 และ 5:
  - ตัวละครยืนชิดขอบล่างของพื้นที่เวที (ส่วนเอวจมอยู่หลังกล่องข้อความ/แผงการ์ดด้านล่างอย่างเป็นธรรมชาติ)
  - **แถบปลอดภัยของใบหน้า (`52–68%` จากขอบล่างจอ):** ดวงตาของตัวละครทั้งฝั่งซ้าย (`28%`) และฝั่งขวา (`72%`) ต้องอยู่ในแถบนี้ และ **ห้ามมีกรอบ UI, ป้ายเจตนา หรือการ์ดปุ่มใด ๆ ล้ำขึ้นมาบังใบหน้าตัวละครเด็ดขาด**
  - ผู้ที่กำลังพูดมีความสว่าง `100%` ส่วนคู่สนทนาลดความสว่างลงเล็กน้อยเหลือ `88%`

### 3.4 Master Component 3 & 4: `<SaaDialogueCard />` และ `<TactileActionCard />`

1. **กล่องบทพูด (`<SaaDialogueCard />`):**
   - พื้น `#FCF4E3` ขอบมน `18px` เส้นขอบ `#D6C6A5` เงาอุ่นบาง ๆ ลายน้ำใบบัวมุมขวาล่าง
   - ป้ายชื่อผู้พูดสี `#23382C` ลอยทับขอบบนซ้าย พร้อมลูกศรอ่านต่อ `▽` มุมขวาล่าง
   - **ห้ามแสดงปุ่มตัวเลือกซ้อนพร้อมกับกล่องบทพูดยาว** (เมื่อเข้าจุดตัดสินใจ ให้ย่อบทนำเหลือแถบสรุปสถานการณ์สั้น ๆ 1–2 บรรทัดไร้ลูกศร `▽` แล้วแสดงการ์ดตัวเลือกแทน)
2. **การ์ดปุ่มกดมาตรฐานเดียว (`<TactileActionCard />`):**
   - ใช้รูปทรงการ์ดกระดาษสา `#FCF4E3` ขอบมน `14px` แบบเดียวกันทั้งใน **ทางเลือกเนื้อเรื่อง (โหมด 1), ปุ่มศึกประชันเงา (โหมด 2) และการ์ดกิจกรรมแคมป์ (โหมด 3)** เพื่อคุมเอกภาพของเกม!
   - แยกความหมายด้วย **แถบสีขอบซ้าย + รูปไอคอนจริงด้านซ้าย (`40×40 px`) + ป้ายแท็กมุมขวา** เท่านั้น:
     - **ท่าผสาน (`Item × Bond Combo`):** ขอบฝีเข็มประสีทอง `2px dashed #9A6B12` พื้นอุ่น `#FFF8E6` ด้านซ้ายวาง **รูปไฟล์ไอเทมจริง `512×512`** ซ้อนคู่กับกรอบกลมหน้าสหายจริง
     - **ปุ่มชนะทางบอส (`Counter` ในโหมด 2):** มีป้ายแคปซูลสีทอง `#E7A93B` ตัวอักษรเข้ม `แก้ทาง`
     - **ปุ่มทักษะครอบครัวที่ใช้ซ้ำ (`Homesick Warning`):** มีป้ายแคปซูลสีฟ้าหม่น `#6E87AC` คำว่า `ซ้ำ`
     - **การ์ดแคมป์ที่เลือกแล้ว (โหมด 3):** ขอบสีเขียวมอส `#4E8C57` `2px` พร้อมป้ายเล็ก `เลือกแล้ว` (ห้ามเขียนคำบรรยายย่อย 2 บรรทัดแบบคู่มือทางการ ให้แสดงเฉพาะชื่อกิจกรรมในเรื่อง + ผลลัพธ์สั้น ๆ เช่น `สายใยเตื๊อก +` หรือ `แรง +●●`)

### 3.5 Master Component 5: `<ThreeStrandDestinyCard />` (โหมด 5 — Desktop และ Mobile ต้องเป็นดีไซน์เดียวกัน!)

  - ส่วนบนของการ์ดแต่ละใบแสดง **เส้นด้ายฝ้าย 3 เกลียว** (`เกลียวสถานะ` · `เกลียวสายใย` · `เกลียวของแทนใจ`) ถักรวมกันลงมาผูกเป็น **ปมด้ายฝ้ายกลม** ตรงกลาง (ห้ามนำเหรียญกระดุม `ต.♡ป.` ไปแปะในฉากจบกลับบึง และห้ามใส่กรอบรูปวิวสี่เหลี่ยมคนละสไตล์!)

## 5. ขั้นตอนปฏิบัติการ 4 ขั้นแบบประหยัดโควตาและแม่นยำ 100%

1. **ขั้นที่ 1 — เตรียมกรอบอุปกรณ์ต้นแบบ 2 กรอบ และภาพฐานไร้ตัวอักษร (Reuse ก่อนเจนใหม่):**
   - สร้างหรือสกัดกรอบอุปกรณ์มาตรฐานเพียง **2 ไฟล์** คือ `frame-macbook-chrome.png` (มีช่องจอ `1440×900` และแถบ Chrome `https://t3thr.github.io/JaoKob/`) และ `frame-iphone-safari.png` (มีช่องจอ `390×844` Dynamic Island ด้านบน และแถบ Safari `t3thr.github.io/JaoKob/` ด้านล่าง) เพื่อนำไปครอบทุกรูปให้กรอบเครื่องเหมือนกันทุกพิกเซล
   - สำหรับภาพฐานซูมมือในโหมด 4 และภาพเงาผนังโหมด 2 ให้ตรวจดูภาพฐานไร้ตัวอักษรที่มีอยู่แล้วก่อน หากมีตัวหนังสือติดอยู่จึงเจนเฉพาะภาพฐานเปล่าแบบ **ห้ามมีตัวอักษรใด ๆ ในภาพ (`ZERO TEXT IN GENERATED PLATE`)**
2. **ขั้นที่ 2 — สร้างชุด Component กลางชุดเดียว (`docs/design-system/ux-mockups/v2/harness/`):**
   - เขียนไฟล์ `ux-components.css` เพียงไฟล์เดียวที่นิยาม `<TopHudCapsule />`, `<VnTachieStage />`, `<SaaDialogueCard />`, `<TactileActionCard />`, `<ClashIntentAndGauge />` และ `<ThreeStrandDestinyCard />` พร้อม SVG ไอคอนโลกของกบ (`ใบบัว`, `ดาวสามแฉก`, `ขากบสามนิ้ว`, `สร้อยด้ายถัก 3 สีมีปม`, `กระเป๋าสานกก 4 ช่อง`)
   - สร้างหน้า HTML ที่รับพารามิเตอร์ `?screen=1..10` เพื่อเรนเดอร์แต่ละหน้าจอจาก Component ชุดเดียวกันและดึงไฟล์ภาพตัวละคร `Tachie v2` / ไอคอนของสะสมจริงมาแสดง
3. **ขั้นที่ 3 — เรนเดอร์ด้วย Native macOS Chrome CLI และประกอบกรอบอุปกรณ์ด้วย Python `Pillow`:**
   - รันคำสั่ง Chrome Headless ที่มีอยู่ในเครื่องโดยตรง (เช่น `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=2 --window-size=1440,900 --screenshot=...`) สำหรับ Desktop และ `--window-size=390,844` สำหรับ Mobile
   - ใช้สคริปต์ Python `Pillow` ประกอบภาพหน้าจอที่เรนเดอร์เสร็จลงในกรอบ `frame-macbook-chrome.png` และ `frame-iphone-safari.png` แล้วบันทึกทั้ง `.png` และ `.webp` ลงใน `docs/design-system/ux-mockups/v2/`
4. **ขั้นที่ 4 — ตรวจรับ 12 ข้อ (Self-Audit Gate) และสร้างหน้าเปรียบเทียบ `v1 → v2`:**
   - เปิดไฟล์ภาพ `.png` ทั้ง 10 ไฟล์ใน `docs/design-system/ux-mockups/v2/` ตรวจด้วยสายตาทีละภาพว่า:
     1. `<TopHudCapsule />` หน้าตาเหมือนกันทุกพิกเซลในทุกโหมด
     2. ไอคอน `ใจ` เป็นดาวสามแฉก และ `แรง` เป็นขากบสามนิ้วทุกรูป
     3. ไม่มีกระเป๋าเป้หนังมนุษย์ ไม่มีรอยเท้าคน 5 นิ้ว ไม่มีเหรียญ `ต.♡ป.` ในฉากจบกลับบึง
     4. คำภาษาไทยสะกดถูกต้อง 100% (`ดามข้อเท้า`, `เตื๊อก`, `กระดุม`, `ยืนด้วยลำแข้ง`, `ต.♡ป.`)
     5. ไม่มี UI ชิ้นใดทับแถบใบหน้า `52–68%` ของตัวละคร
     6. Desktop และ Mobile ของโหมดเดียวกันใช้สไตล์การ์ดเดียวกัน 100%
   - สร้างหน้า HTML เปรียบเทียบ Before (`v1`) → After (`v2`) ที่ `docs/design-system/evidence/ux-mockups-v2-review.html` และแนบรูปที่เสร็จแล้วแสดงในแชทตอบกลับให้ PO ตรวจทันที
