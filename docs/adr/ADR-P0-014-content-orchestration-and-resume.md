# ADR-P0-014: Pure Content Orchestration, Resume and Save Consent

Status: Accepted implementation direction under Tech Lead Step 3 directive; final integrated diff awaits owner review.

Date: 2026-09-04. Trace: CR-0002 D3/D4, FR-ENG-001/002/003/008, FR-STA-001/004, FR-SAV-001/003/006/007/009, FR-LOC-001/002, GDD-UX-003, ADR-P0-004/006/007/013.

## Context and authority

Tech Lead Step 3 authorizes selection and implementation of pure orchestration, save compatibility/consent, idempotent Resume and Mock deprecation. Content 2.0.0/package schema 1.1.0 is implemented at a85a5e5. Save format 1 and the six-state transition table remain unchanged. This closes the implementation choices in CR-0002 D3/D4; it does not supply human editorial or accessibility approval.

## Decisions

1. Data loads/validates JSON and normalizes immutable records into an inward-facing catalog. A capability gate rejects unimplemented execution features before play. The scoped executor supports cutscene/exploration/decision, node-entered events, condition DSL and existing flag/metric policies. It does not add Act 2, event redirects or artificial crisis/ending nodes. Core imports no data/UI, parses no JSON, and reads no browser/storage API.
2. Pure orchestration receives catalog, snapshot, command/revision, timestamp, session ID and elapsed time. It uses the existing condition evaluator, meter arithmetic, Choice Transaction and State Machine. Ordering is pre-action guard → candidate effects → target guard → transition → target entry effects/events → dialogue cursor → immutable candidate. The root commits one candidate, saves, then renders. Invalid or stale commands return the original snapshot.
3. `progress.viewedDialogueIds` remains a unique collection of actually displayed dialogue IDs, ordered by most recent display (move-to-end). Its last item identifies the current page in the current node's deterministic dialogue sequence. No synthetic ID, new flag or schema field is added. Revisiting a hotspot moves the displayed line to the end without forgetting previously viewed lines. `completedNodeIds` records leaving a node; final rest is completed only after the last page is acknowledged.
4. Node-entered events execute once up to maxOccurrences. Selected event dialogue precedes base dialogue. Decision/exploration with event dialogue exposes actions on the final preface page, together with the prompt/description; cutscene advances explicitly. The supported package has no replayable dialogue-bearing event slots whose condition changes after firing; the capability gate rejects ambiguous or unrepresentable cases rather than inferring a cursor.
5. Resume validates the Save Envelope and content references/policies/cursor/causal event prerequisites, then restores the saved payload without entry effects or occurrence changes. TR-003 admits rehydration through a transient Cutscene plan; saved Exploration/Decision use TR-005/TR-006 admission facts before exposing the restored snapshot. No intermediate state/node mismatch is rendered or saved. This is restoration, not a story transition or a fake content node.
6. Before-node checkpoint captures pre-entry domain facts; retry restores those facts then enters once. After-node checkpoint captures completed rest. Checkpoints do not acquire cursor fields: before-node retry begins at the first line, after-node rest remains complete. Before-node retry clears downstream completed-node markers while retaining historical viewed dialogue IDs, so an earlier checkpoint cannot silently skip the rest pages. Resume uses the active payload's exact cursor. Settings remain application-owned and survive retry. Canon Act 1 never reaches zero HP/Sanity; unsupported crisis content fails safely and retains the pre-command snapshot, while existing Core crisis/retry regression remains intact.
7. The root holds Title as application presentation with no active domain snapshot. At completed act-rest it retains the saved/in-memory candidate and closes the active session to Title; no new Cutscene→Title transition is invented. The completion action accurately distinguishes saved data from a memory-only session.
8. Recovery is read-only. Mixed/incompatible/corrupt/future records block automatic replacement; a valid recoverable candidate may be played in memory while raw records remain intact. New Game over existing records requires a separate localized confirm/cancel screen. Confirmation uses an adapter recovery token and rechecks exact raw records before clearing only owned save keys; changes since consent cancel the clear. A failed clear never starts a writable replacement session. A conservative adapter write predicate rechecks content compatibility inside both stage and commit; malformed or incompatible records appearing after the application preflight are preserved. This adds no Save Schema field and leaves legacy adapter callers unchanged. Storage failures preserve play through an explicit memory-only notice.
9. Each accepted domain action increases revision once, including page advancement. Every page/choice/interaction is autosaved, so pagehide need not create a conflicting same-revision write. Bootstrap rejects simultaneous inputs and renderer intents from obsolete views. Reading settings persist with a new revision via a pure metadata touch, preserving story state/cursor/flags. High/irreversible choices have an explicit confirm/cancel screen when the setting enables it; confirmation itself does not change domain state.
10. Mock package and former bootstrap move to test fixtures/helpers; original Sprint 1 assertions continue exercising Core/renderer/persistence. New integration tests cover the production composition root and all Canon paths. Main runtime has no import path to Mock or tests. System strings live in Data localization; renderer consumes immutable localized View Models through safe DOM APIs.

## Alternatives and consequences

Adding a save cursor field or a new state would break the sprint constraint. Encoding cursor IDs in flags/history would misrepresent their contracts. A viewed-ID recency order preserves the existing unique set, uses real dialogue references, and is testable on revisits. Runtime content capability validation must ensure a deterministic sequence and stable conditional slots; future richer event/cursor semantics need a new reviewed contract.

No automatic Mock-to-Act-1 migration is attempted because its IDs/effects differ. Explicit replacement consent is clearer than guessing a checkpoint. Recovery tokens are adapter-local opaque handles, not persisted player data or security credentials. LocalStorage has no multi-key transaction/CAS: staged writes, monotonic guards and conservative compatibility checks reduce cross-tab conflicts, but do not claim transactional isolation across processes. Human review still gates merge; tests do not certify universal WCAG conformance.

## Verification, migration and rollback

Verify exact cursor and snapshot round trips at every page/state, no entry-effect replay, all twelve Canon outcomes, hotspot replay, stale/double input, consent cancel/confirm/race, storage faults, malformed content and old/future/corrupt saves. Run existing units plus real browser root/subpath journeys, keyboard controls, Bond absence from DOM/accessibility tree, safe text injection, screenshots and network/error inspection.

Save Schema and State Machine stay byte-identical. There is no implicit save migration. A rollback requires a reviewed revert that retains the compatibility write guard (or disables writes), preserving 2.0.0 records. A raw revert that removes this guard is unsafe because the former Mock root did not provide replacement consent. A test-only legacy composition with the retained guard demonstrates that New Game cannot downgrade/overwrite 2.0.0 records. A user-authorized replacement can remove old records, as clearly stated in the confirmation. Supersedes: none; implements the pending execution decisions referenced by ADR-P0-013.
