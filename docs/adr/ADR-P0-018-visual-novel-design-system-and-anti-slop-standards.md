# ADR-P0-018: Visual Novel Design System, Layout Anchoring, and Anti-Slop Presentation Standards

Status: **Accepted — binding design standard for Sprint 4 UI Overhaul and future frontend slices.**

Date: 2026-10-15. Authority: **PO & Tech Lead Consensus (Playtest Feedback Review)**. Version: 1.0.0.

## Context

ผลจากการทดสอบจริงร่วมกับผู้เล่นสาย Visual Novel บนพรีวิวของ Sprint 4 Slice 1 (PR #13, commit `093595d`) พบปัญหาด้าน UX/UI ขั้นวิกฤต 4 ประการที่ทำให้ประสบการณ์การเล่นสูญเสียมาตรฐานงานฝีมือ และแสดงพฤติกรรมแบบ "AI Slop" อย่างเด่นชัด:

1. **ขาดความมั่นคงของเลย์เอาต์ (Layout Instability & Shifting):** เมื่อผู้เล่นเปลี่ยนจากหน้าจออ่านบท (Reading Beat) ไปสู่หน้าจอเลือกการกระทำ (Decision Crossroads) การ์ดข้อความและปุ่มตัวเลือกเกิดอาการกระโดด เปลี่ยนความสูง และขยับตำแหน่งขึ้นลงไปมา ไร้แกนยึด (Anchor) ที่แน่นอน ทำให้สายตาต้องคอยปรับโฟกัสตลอดเวลาจนเกิดความล้า (Visual Fatigue) ขัดกับมาตรฐานสากลของเกม Visual Novel
2. **สถาปัตยกรรมหน้าต่างตั้งค่า (Settings Dialog UX):**
   - ปุ่มปิดหน้าต่าง (`settings.close`) ถูกวางไว้ที่ด้านล่างสุดของฟอร์ม ทำให้ผู้เล่นบนหน้าจอมือถือหรือเมื่อมีการขยายขนาดตัวอักษรต้องเลื่อนหน้าจอ (Scroll) ลงไปจนสุดจึงจะกดปิดได้
   - ตัวเลือกเปิด/ปิด (Toggles) ใช้เพียง `<input type="checkbox">` ดิบๆ ที่ขาด Visual Feedback ชัดเจนว่าสถานะปัจจุบันคือ "เปิด" หรือ "ปิด"
   - ปุ่มควบคุมเสียงกดยาก หรือเปลี่ยนสถานะโดยผู้เล่นไม่ทราบแน่ชัด
3. **แบบแผนการสร้างชิ้นงานแบบ AI Slop (AI Slop Patterns):**
   - การใช้เครื่องหมาย Em Dash (`—`) ในภาษาไทยตามจุดต่างๆ (เช่น ชื่อเรื่อง `เจ้ากบ — บ้านในหนองน้ำ`) ซึ่งเป็นรูปแบบการแปลหรือเจนข้อความจาก AI ที่ขัดกับไวยากรณ์และความคุ้นชินของวรรณศิลป์ไทย
   - การใช้ Unicode Emoji (เช่น `⚙`, `🪷 🔒`, `♥`) เป็น Fallback Icon ใน DOM Renderer แทนการใช้ Vector SVG Iconography มาตรฐาน
4. **การแสดงคำเตือนเนื้อหาแบบโจ่งแจ้ง (Blunt Content Warning Banner):**
   - ป้ายคำเตือนเรื่องพายุและการพลัดพรากถูกนำมาแปะหราเป็นกล่องทึบใต้ปุ่มเริ่มเกมบนหน้า Title ส่งผลให้บรรยากาศนิทานภาพถูกทำลาย และให้ความรู้สึกเหมือนเว็บราชการหรือข้อความแจ้งเตือนระบบ

## Decision

ที่ประชุม PO และ Tech Lead มีมติกำหนดมาตรฐานสถาปัตยกรรม UI/UX ดังต่อไปนี้เป็นข้อบังคับ (Mandatory Standards):

### 1. D1 — กฎการยึดตำแหน่งกล่องสนทนาให้คงที่ (Stable Dialogue Anchor)
- กล่องบทอ่าน (Reading Card) และส่วนแสดงผลตัวเลือก (Decision Interface) ต้องยึดอยู่กับ **Fixed Bottom Baseline** เสมอ (เช่น `position: absolute / fixed; bottom: 24px; left: 50%; transform: translateX(-50%)`)
- การเปลี่ยนโหมดจาก Reading Beat ไปสู่ Decision Crossroads **ต้องไม่ทำให้กล่องข้อความขยับตำแหน่งขึ้นลงอย่างรวดเร็ว**
- ปุ่มตัวเลือกต้องมีตำแหน่งการแสดงผลที่สมมาตรและเสถียร โดยอาจวางซ้อนอยู่เหนือกล่องข้อความ หรือจัดสรรพื้นที่ในแกนแนวตั้งที่มีความสูงคงที่ (Reserved Vertical Slot) เพื่อขจัดปัญหา Layout Shift (CLS) ให้เป็นศูนย์

### 2. D2 — การจัดวางหน้าต่างตั้งค่าและสวิตช์เปิดปิด (Ergonomic Modal & Toggle Standards)
- หน้าต่าง `dialog.jk-settings-dialog` ต้องมี **ปุ่มปิดแบบไอคอนกากบาท (Fixed Corner Close Button: `✕`)** ตรึงอยู่ที่มุมบนขวาเสมอ (`position: sticky / absolute; top: 1rem; right: 1rem; z-index: 10`) เพื่อให้ผู้เล่นสามารถปิดหน้าต่างได้ทันทีจากทุกระยะการเลื่อน
- สวิตช์ควบคุมทุกตัวต้องได้รับการออกแบบตามมาตรฐาน Switch Control สากล (Styled Toggle Switch ที่มี Track ชัดเจน และ Thumb ที่สไลด์เปลี่ยนฝั่ง) พร้อมแสดงสีและป้ายบอกสถานะ On/Off ที่สายตามองเห็นได้เด็ดขาด (เช่น สีเขียวมอสส์เมื่อเปิด และสีเทาหม่นเมื่อปิด พร้อมรองรับ `role="switch"` และ `aria-checked`)
- ตัวควบคุมเสียงต้องแสดงสถานะการทำงานจริงอย่างโปร่งใส ไม่หายไปหรือเปลี่ยนโครงสร้างปุ่มกะทันหัน

### 3. D3 — ขจัดมลภาวะ AI Slop ในงานภาษาและไอคอน (Anti-Slop Typography & Iconography)
- **ห้ามใช้เครื่องหมาย Em Dash (`—`) ในข้อความภาษาไทยทุกจุด:** ในตำแหน่งชื่อเรื่องหรือการคั่นคำ ให้ใช้เครื่องหมายทวิภาค (`: `), วงเล็บ, หรือการเว้นวรรคตามธรรมชาติของภาษาไทย (เช่น `เจ้ากบ: บ้านในหนองน้ำ` หรือ `เจ้ากบ ตอน บ้านในหนองน้ำ`)
- **ห้ามใช้ Emoji ตกยุคเป็น Icon ในระบบ:** ให้ยกเลิกการส่งสตริง Emoji เป็น Fallback ของ Icon ใน `dom-renderer.js` ทั้งหมด และบังคับให้ทุกไอคอนเรนเดอร์ผ่านระบบ Vector SVG สโตรกสะอาด (`chrome-icons.js`) เท่านั้น

### 4. D4 — การแสดงคำเตือนและข้อสังเกตอย่างสุขุม (Discreet Floating Notice Architecture)
- นำกล่องคำเตือนเนื้อหาขนาดใหญ่ออกจากกึ่งกลางหน้า Title โดยเด็ดขาด
- ให้เปลี่ยนเป็น **ไอคอนแจ้งเตือนขนาดกะทัดรัด (Floating Notice / Info Icon)** วางไว้ที่มุมจออย่างแนบเนียน (เช่น บริเวณ Utility Rail ด้านบน หรือมุมขวาล่าง)
- เมื่อผู้เล่นกดที่ไอคอน จึงจะเปิดหน้าต่างป๊อปอัปแจ้งเตือนเนื้อหา (Content Advisory Modal) ที่มีปุ่ม "รับทราบ" พร้อมตัวเลือกเช็คบ็อกซ์ **"ไม่ต้องแสดงคำเตือนนี้อีก (Don't show again)"** โดยบันทึกการตั้งค่านี้ลงใน Storage เพื่อไม่ให้ปรากฏขึ้นมารบกวนผู้เล่นซ้ำอีก

### 5. D5 — การจัดระบบ Design System Tokens & Spatial Rhythm
- กำหนดระบบ Spacing แบบ 8-point grid (4px, 8px, 16px, 24px, 32px) อย่างเคร่งครัดใน `tokens.css` และ `layout.css`
- ตรวจสอบอัตราส่วนความเปรียบต่างของสี (Color Contrast Ratio) ระหว่างตัวอักษรและพื้นหลังกระดาษสา ให้ผ่านเกณฑ์ WCAG AA (อย่างน้อย 4.5:1 สำหรับข้อความปกติ และ 7:1 สำหรับ High Contrast)

## Consequences

- โค้ดใน `src/ui/styles/` (`tokens.css`, `layout.css`, `components.css`), `src/ui/components/settings-dialog.js`, และ `src/ui/renderers/dom/dom-renderer.js` ต้องได้รับการปรับปรุงให้สอดคล้องกับ ADR นี้
- ข้อกำหนดใน Task T1 และ T2 ของ Sprint 4 ต้องนับรวมเกณฑ์ตาม ADR-P0-018 เป็นเงื่อนไขการตรวจรับ (Acceptance Criteria)
- PR #13 ต้องได้รับการปรับปรุงและผ่านการทดสอบตามมตินี้ก่อนจึงจะสามารถ Merge เข้าสู่ `develop` ได้
